# Sub-fase 14.02: Persistencia PostgreSQL y API central

- **Fase:** [14 — Plataforma central en la nube](./README.md).
- **Estado:** Pendiente; fuera del MVP.
- **Dependencia:** [Identidad y decisiones de plataforma](./14.01-identidad-y-plataforma.md) completada.

## Objetivo

Implementar referencias y consultas centrales respetando los puertos de aplicación.

## Tareas

- [ ] Crear el adaptador PostgreSQL y las migraciones forward-only sin alterar el driver SQLite local.
- [ ] Modelar sucursal, almacén, correspondencia de producto, metadatos de sincronización y proyecciones de lectura; conservar unidad/escala y timestamps UTC.
- [ ] Definir representación exacta de agregaciones y su transporte JSON, incluyendo valores fuera del rango seguro de number.
- [ ] Implementar puertos de consulta y rutas Fastify con autorización por sucursal, límites y paginación determinista.
- [ ] Registrar el esquema del inbox/progreso que implementará Fase 15 sin declarar sincronización entregada.
- [ ] Probar restricciones, transacciones, consultas autorizadas y migraciones contra PostgreSQL real de pruebas; un fake no cierra la aceptación del adaptador.

## Criterios de aceptación

- La API no permite obtener existencia de una sucursal no autorizada mediante filtros o IDs.
- Las consultas no mezclan unidades/escalas y conservan precisión en sus totales.
- Las migraciones se ejecutan sobre una base nueva y una base de la versión anterior con evidencia de conservación.
