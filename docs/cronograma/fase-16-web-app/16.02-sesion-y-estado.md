# Sub-fase 16.02: Sesión, consultas y estado de interfaz

- **Fase:** [16 — Web App interna con Next.js](./README.md).
- **Estado:** Pendiente; fuera del MVP.
- **Dependencia:** [Experiencia de usuario y selección del stack](./16.01-experiencia-y-stack.md) completada.

## Objetivo

Integrar datos autorizados y estado de UI sin fugas entre usuarios.

## Tareas

- [ ] Implementar sesión cloud y navegación según permisos con autorización efectiva en la API Fastify.
- [ ] Separar Server Components y Client Components; cualquier BFF adapta transporte/sesión sin reglas de inventario ni SQL.
- [ ] Integrar TanStack Query con claves por contexto autorizado y filtros, políticas explícitas de revalidación, cancelación y errores.
- [ ] Si se usa SSR/prefetch, aislar QueryClient por solicitud, hidratar coherentemente y evitar caché compartida de respuestas privadas.
- [ ] Ubicar filtros compartibles en URL y preferencias/estado transversal de UI en Zustand cuando proceda; aislar stores en SSR y no duplicar inventario remoto.
- [ ] Cancelar peticiones y purgar caché sensible al salir, cambiar de usuario o perder permisos; probar cambios de sesión y respuestas tardías.

## Criterios de aceptación

- Dos sesiones concurrentes no comparten datos por SSR, QueryClient, Zustand ni caché de Next.js/CDN.
- Recargar un enlace conserva filtros válidos y revalida su autorización.
- Un refetch exitoso no cambia artificialmente la fecha de actualización del inventario de origen.
