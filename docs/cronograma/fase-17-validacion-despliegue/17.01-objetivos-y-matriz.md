# Sub-fase 17.01: Objetivos y matriz de validación

- **Fase:** [17 — Validación integral y despliegue gradual](./README.md).
- **Estado:** Pendiente; fuera del MVP.
- **Dependencia:** Fase 16B cerrada; gates de piloto/producción aplicables antes de activar operación real.

## Objetivo

Fijar los criterios medibles que determinarán la aceptación del despliegue.

## Tareas

- [ ] Acordar sucursales, almacenes, productos, lotes, movimientos, usuarios concurrentes y dispositivos de prueba.
- [ ] Fijar objetivos numéricos de actualización con conexión, atraso tolerable, recuperación, pérdida de datos admisible y rendimiento web/API.
- [ ] Definir escenarios de conectividad degradada y límites operativos, con política de aviso y recuperación.
- [ ] Revisar evidencia de fases previas y construir una matriz requisito → prueba → resultado → responsable.
- [ ] Definir criterios de entrada/salida por sucursal y los gates de piloto/producción que debe cumplir cada activación.

## Criterios de aceptación

- La aceptación utiliza valores acordados antes de medir, no objetivos inventados después del resultado.
- Cada riesgo de FS-009 y FS-010 tiene un ensayo o una brecha que impide el despliegue dependiente.
- Existe responsable y evidencia requerida para cada paso de activación.

## Verificación y cierre

Registrar pruebas/evidencia correspondientes a los criterios; una expectativa futura no
se presenta como garantía implementada. Ejecutar las verificaciones de la fase y marcar
solo tareas ejecutadas como `- [x] ~~tarea~~`. Mantener actualizados README de fase e
índice maestro conforme al [plan transversal](../evolucion-post-mvp.md).
