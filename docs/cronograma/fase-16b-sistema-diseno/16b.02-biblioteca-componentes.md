# Sub-fase 16B.02: Biblioteca de componentes y patrones

- **Fase:** [16B — Sistema de diseño propio de Cullen](./README.md).
- **Estado:** Pendiente; fuera del MVP.
- **Dependencia:** [Identidad visual y tokens](./16b.01-identidad-y-tokens.md) completada.

## Objetivo

Convertir la base shadcn/ui en una biblioteca propia mantenible.

## Tareas

- [ ] Crear la biblioteca prevista en packages/ui con exports públicos y límites servidor/cliente compatibles con Next.js.
- [ ] Adoptar el código base de shadcn/ui y la familia de primitivas elegida, conservando procedencia, versiones y avisos aplicables.
- [ ] Implementar componentes de navegación, campos, selectores, diálogos, tablas, paginación, indicadores y estados vacíos/carga/error.
- [ ] Componer patrones de inventario como selector sucursal/almacén, cantidad con unidad, frescura y detalle; reciben datos preparados sin consultar APIs.
- [ ] Separar estado remoto TanStack Query y estado de pantalla/Zustand de los componentes presentacionales reutilizables.
- [ ] Probar comportamiento de componentes interactivos y contratos de exports; documentar variantes y reglas de composición.

## Criterios de aceptación

- La biblioteca se consume mediante exports públicos y no depende de drivers, inventario ni credenciales.
- Los patrones cubren el inventario de pantallas acordado con variantes coherentes.
- Teclado, foco y semántica siguen funcionando al personalizar los componentes base.
