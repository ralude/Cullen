# Sub-fase 16B.03: Documentación visual y pruebas

- **Fase:** [16B — Sistema de diseño propio de Cullen](./README.md).
- **Estado:** Pendiente; fuera del MVP.
- **Dependencia:** [Biblioteca de componentes y patrones](./16b.02-biblioteca-componentes.md) completada.

## Objetivo

Dar al sistema de diseño una referencia ejecutable y un proceso de mantenimiento.

## Tareas

- [ ] Adoptar Storybook o la herramienta equivalente seleccionada en 16.01 para documentar tokens, componentes, variantes y uso.
- [ ] Crear ejemplos de estados habituales, extremos y degradados con datos sintéticos claramente identificados.
- [ ] Automatizar pruebas de interacción, regresión visual y accesibilidad con herramientas compatibles; complementar con revisión manual.
- [ ] Documentar API de componentes, patrones permitidos, límites de uso y proceso de revisión de nuevas contribuciones.
- [ ] Definir versionado, cambios incompatibles y actualización de código upstream sin sobrescribir personalizaciones a ciegas.

## Criterios de aceptación

- Cada componente público tiene ejemplos y guía de uso.
- Una regresión de interacción o presentación relevante produce evidencia reproducible.
- El equipo puede actualizar la base shadcn/ui con trazabilidad de cambios y personalizaciones.

## Verificación y cierre

Registrar pruebas/evidencia correspondientes a los criterios; una expectativa futura no
se presenta como garantía implementada. Ejecutar las verificaciones de la fase y marcar
solo tareas ejecutadas como `- [x] ~~tarea~~`. Mantener actualizados README de fase e
índice maestro conforme al [plan transversal](../evolucion-post-mvp.md).
